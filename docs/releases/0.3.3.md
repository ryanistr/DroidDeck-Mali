# DroidDeck 0.3.3 (Mali)

This build is the Mali fork's fix for the two bring-up crashes reported from the GT 20 Pro
(MediaTek MT6896, Mali-G610) and the GT 30 Pro (MediaTek MT6897, Mali-G615).

### Fixed

- **Mali-G615 (Valhall gen3) has a PanVK backend now.** The PanVK driver this fork ships carried
  backends for Valhall gen1 (v9, Mali-G77) and gen2 (v10, Mali-G610) only, so a GT 30 Pro was
  handed a driver that could not create a GPU device at all: the session died at
  `failed to find physical device`, and gamescope exited with code 1. Valhall gen3 (v11) is built
  into the driver again.
- **Mali-G610 no longer falls back to software rendering.** The app only counted v9 as a usable
  PanVK generation, so a GT 20 Pro was routed to lavapipe even though the shipped driver has a
  working v10 backend. The list now matches what the driver is built with.
- **A Vulkan driver the runtime does not carry is no longer handed to the loader.** Pointing
  `VK_ICD_FILENAMES` at an ICD manifest whose library is missing leaves the loader with zero
  drivers, so `vkCreateInstance` returns `VK_ERROR_INCOMPATIBLE_DRIVER` (`-9`) and gamescope
  aborts on its assertion (the GT 20 Pro's exit 134). A manifest whose `library_path` does not
  resolve inside the runtime is now ignored.
- **GPU detection on MediaTek devices with a newer Mali.** `mt6897` reports as `Mali-G615 MC6`
  instead of an unknown Mali, and a generation without a backend here is reported as unsupported
  rather than routed to a driver that cannot drive it.

### Notes

- Sessions on Mali Valhall remain experimental. PanVK runs through ARM's proprietary
  `mali_kbase` kernel driver, with the compositor and the guest sharing one driver.
- The PanVK driver in this build is `PanVK-rynx-1.2.0-p6`
  (`sha256 bafaaa402ce669a9a1fb3ca364b4dee3abab86803a55396c176541d6c92b1e5f`), built from the
  pinned `mesa-panvk-mali-g57 v1.2.0` tree with the fork's patches applied.
